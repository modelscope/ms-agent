# 个性化与项目指令

个性化文件告诉智能体怎样与你协作；项目指令提供当前工作目录的约定。它们不是长期记忆的别名，也不是当前一次任务的完整描述。

## 文件的职责

| 文件 | 适合放什么 |
| --- | --- |
| `SOUL.md` | 助手行为与协作方式 |
| `AGENTS.md` | 项目结构、开发约定、检查命令及边界 |
| `PROFILE.md` | 用户称呼、沟通偏好和适合复用的信息 |

全局home与工作目录的文件按解析规则参与装配；不要假设任意父目录的同名文件都会被读取。默认模板有伴随状态记录，用户修改过的内容不应被框架模板升级覆盖。

## 在自定义配置中启用

```yaml
personalization:
  enabled: true
```

随包通用Agent启用此项，而配置解析层的缺省行为与具体入口可能不同。自包含任务可显式关闭；完整system层的关系见[提示装配](prompts.md)。

在项目的 `AGENTS.md` 写一个小约定，例如：

```markdown
# 项目约定

- 修改前先说明影响的文件。
- 运行测试后报告结果；未运行的检查明确标注。
- 不读取凭据文件，不把真实密钥写入日志。
```

这些是给模型的行为指导，不替代工具权限或访问控制。

## 更新与排查

1. 确认当前项目工作目录及 `MS_AGENT_HOME`。
2. 使用WebUI个性化设置或直接编辑被解析的文件。
3. 保存后在下一轮/新会话确认效果；不要用“模型是否照做”作为唯一加载证明。
4. 若内容缺失，检查空文件、frontmatter/注释剥离和字符限制。

工作区文件的当前注入上限为每文件20,000字符，长文件可能被截断。不要在这些文件中保存秘密；它们可能成为发送给模型的上下文。
