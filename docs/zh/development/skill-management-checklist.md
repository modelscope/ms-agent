# Skill 管理：人工走查清单

按 [WebUI 指南](../user-guide/webui.md)启动服务，在独立测试项目中操作。准备一个自己控制的 Skill：先安装 V1，再提交 V2，文件内保留可读取的版本标记。实现边界见[开发概要](skill-management.md)。

## 安装与来源

| 完成 | 操作 | 预期 |
| --- | --- | --- |
| ☐ | 分别从 GitHub、ModelScope Skill 链接安装到全局和项目 | 候选、来源与提交可查看，安装位置正确；静态检查需确认时有提示 |
| ☐ | 从[公开合集](https://modelscope.cn/collections/Gaodekaifangpingtai/gaodekaifangpingtai-skill)多选安装；有更新时仅升级一个成员 | 无法读取项单独标记；各安装独立更新和恢复，合集成员变化不自动增删本地内容 |
| ☐ | 重复安装，或对同名候选全选再择一 | 已安装项不可重复选择，同名项不互相覆盖 |
| ☐ | 本地导入后关联来源 | 相同内容只补记录；不同内容需确认备份替换 |

## 更新、恢复与执行边界

| 完成 | 操作 | 预期 |
| --- | --- | --- |
| ☐ | 发布 V2，检查更新、预览差异并确认 | 目标 Skill 显示“待更新”；文本、二进制和权限变化可辨认；其他 Skill 的变化不误报 |
| ☐ | 原会话使用过 V1，空闲时更新，再只发“继续” | 内部提醒到达模型，工具读取 V2；聊天气泡仍只有“继续” |
| ☐ | 无修改继续对话；重启服务后修改并继续 | 前者不重复提醒，后者能识别新变化 |
| ☐ | 回复中排队或插话，尝试更新 / 删除；停止后更新并恢复 | 连续执行中拒绝变更；停止后可更新，恢复的排队调用使用新版 |
| ☐ | 加入本地自定义文件，再更新并恢复旧版 | 提示“本地有修改”，默认不覆盖；确认覆盖后仍可恢复自定义文件，再检查可发现更新 |
| ☐ | 预览后修改文件，再确认 | 旧计划失效，要求重新预览 |

## 取消、失败与界面

| 完成 | 操作 | 预期 |
| --- | --- | --- |
| ☐ | 下载中取消；批次部分失败后重试 | 无半安装目录或迟到进度，成功项不重复处理 |
| ☐ | 加载中切换作用域；列表请求失败后重试 | 旧响应不覆盖新作用域；失败保留已有卡片，不冒充空列表 |
| ☐ | 关闭自动检查，再手动检查 | 自动检查停止，手动检查可用 |
| ☐ | 切换中英文、明暗主题并缩窄窗口 | 来源可辨认，无页面横向溢出，滚动与操作按钮可用 |

通知以模型输入、工具调用和会话记录为准，不仅看模型自述。事务中断、消息写入失败、恶意归档、凭据重定向及并发竞争由自动化测试覆盖，不在日常工作空间制造故障。
