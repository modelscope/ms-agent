# 密钥保存与恢复

在 WebUI 中保存模型或搜索 API Key 后，MS-Agent 会加密已登记的凭据字段，调用供应商时再解密。正常使用不需要额外输入密码。这里的 **API Key** 是供应商凭据，**主密钥** 是实例用来加解密这些凭据的钥匙，两者不同。

本页说明当前版本的行为；安装包或镜像需包含此功能。加密能保护被单独复制的配置文件，不能保护同时拿到配置和主密钥的人，也不替代登录、HTTPS 或进程隔离。

## 保存和修改 Key

1. 按[模型设置](model-settings.md)填写提供方的 Key 并保存。首次保存非空凭据时，实例会创建默认主密钥；无法创建时保存失败，不改为明文保存。
2. 重新打开编辑框时不会回填 Key。页面显示“未设置”“已配置”或“密钥不可用”，管理接口不返回明文或密文。
3. 修改地址、名称或模型参数时，不必重新填写 Key；替换 Key 会复用当前主密钥，不会轮换主密钥。
4. 发送一条简短消息确认调用成功。“已配置”只代表已保存，不保证供应商权限和额度可用。

接口中省略 Key 或传 `null` 表示保留，空字符串表示明确清除。自定义客户端应区分这三种情况，避免把空输入当作“保持不变”。

## 从旧版本升级

升级前停止共享数据的服务并备份；按[部署指南](deployment.md)保留数据及已有主密钥。启动新版 WebUI 后，迁移会自动发生：

| 时机 | 处理范围 |
| --- | --- |
| WebUI 后端启动 | 全局 `settings.json` 和所有已登记项目，即使项目尚未打开 |
| 后续读取配置 | 全局模型／工具配置入口检查后来导入的旧配置；SDK 解析项目时检查当前项目 |
| 保存配置 | 新填入的凭据先加密再写盘，已有密文保持不变 |

迁移只改已登记的凭据字段，保留其他配置和消息，不生成额外明文备份。正常升级不要求重新填写 API Key 或重建向量库：主对话、压缩、文件记忆、事实抽取和嵌入模型在各自调用时取得原 Key。迁移需要配置可写，以及可创建的默认主密钥目录或有效的外部主密钥。

**共享同一 home 或项目的 WebUI、TUI、CLI 和 SDK 应一起升级。** 同一系统用户默认共用 `~/.ms_agent`，换终端不会隔离配置；不同 home 也可能打开同一个项目。旧版不能读取新密文。回滚需恢复升级前的数据和对应版本，不能让旧版继续写已迁移目录。

迁移逐文件完成；某个文件损坏、权限不足或混有无法解密的密文时，该文件保留原状，其他文件仍可迁移。WebUI 会记录迁移未完成并保留管理入口。**网页能打开不代表迁移全部成功**；修复问题、重新迁移后再分享配置。

## 主密钥放在哪里

| 配置 | 默认值或要求 |
| --- | --- |
| `MS_AGENT_HOME` | 应用目录，默认 `~/.ms_agent` |
| 默认主密钥 | 规范化后的 home 路径加 `.secrets/master.key`，通常为 `~/.ms_agent.secrets/master.key` |
| `MS_AGENT_SECRET_KEY_FILE` | 可选：预先提供的 Fernet 密钥文件，可只读挂载 |
| `MS_AGENT_SECRET_KEY` | 可选：由平台直接注入的 Fernet 主密钥值 |

两个外部来源只能选一个。显式设置为空、文件缺失或密钥无效时会报错，不回退到默认钥匙。外部主密钥不会被复制到应用目录。Docker 默认使用 `/data`，对应 `/data.secrets/master.key`；[部署示例](deployment.md#credential-volumes)说明如何持久化或挂载外部钥匙。

## 备份、导出与分享

| 操作 | 如何处理 |
| --- | --- |
| 升级、重建容器或迁移自己的服务 | 保留应用数据、实际项目文件和同一把主密钥；分开控制访问，恢复时配对使用 |
| 分享项目或模板 | 清除凭据并排除实际主密钥来源；单独复制已加密的配置只能提供额外保护 |
| 导入已清理的模板 | 填写自己的 Key，使用接收方现有主密钥或首次生成的钥匙 |
| 导入只有密文的配置 | 没有原钥匙不能使用旧 Key；恢复原钥匙，或明确清除旧凭据后重新配置 |

只导出应用目录通常不会包含旁边的默认主密钥；导出父目录、整个用户 home 或容器则可能一起带走。导出方应检查**实际密钥来源**，不能只排除某个固定文件名。实验场等外部产品的导出逻辑由其维护方对接；加密本身不代表它们已实现凭据清理。

## 密钥不可用时恢复

先检查实例是否仍指向原来的 home 和密钥来源、文件是否可读，再恢复原主密钥。现有消息仍可查看，但依赖不可解密凭据的调用会失败。系统不会用环境变量凭据掩盖解密失败，也不会因为丢失钥匙就自动生成另一把；原本没有保存 Key 的配置仍按原有环境变量规则工作。

如果确认放弃已保存的凭据，先停止使用这些目录的服务，再执行以下命令。将路径替换为实际应用目录：

```bash
python -m ms_agent.config.secrets reset --home /path/to/ms-agent-data --confirm
```

命令清空全局和所有已登记项目的敏感字段，保留提供方、模型、项目定义和历史消息。未登记项目可增加 `--project /path/to/project`。这是清除整个指定范围的凭据，不只清除当前会话。

已有主密钥不会被替换。默认钥匙丢失且旧密文已清空后，首次保存新 Key 才会创建新钥匙；外部来源仍需修复。没有原钥匙，这个操作不能恢复旧 API Key。

## 保护范围

受管配置中的提供方、LLM、搜索，以及记忆事实抽取和嵌入 Key 已接入。项目 `.ms_agent/config.yaml`、`settings.local.json` 和旧 `memory/*.yaml` 中的登记字段也会处理；新历史快照移除凭据。`${...}` 引用保留原有解析方式。

任意手写 `agent.yaml`、`.env`、MCP env/headers、自定义工具字段、消息正文、日志和既有备份不在全面保护范围内。新增字段需主动接入，见[凭据存储设计](../development/credential-storage.md)。
