# 记忆管理

记忆适合保存需要跨会话复用的知识和偏好，不适合充当完整聊天备份。查看原始对话请使用[会话历史](projects-sessions.md)，控制输入长度请看[上下文](../core/context.md)。

## 查看项目记忆

在项目首页右侧的“记忆”区域查看状态。“当前项目未开启记忆”和“暂无记忆内容”分别表示未开启与已开启但为空；加载失败则需检查后端。

首次使用文件记忆：

1. 进入 **设置 → 个性化 → 记忆设置**。
2. 打开“新建项目时默认开启记忆”，默认后端选择“文件”。设置只影响之后创建的项目，不改动现有项目。
3. 返回工作台，点击左侧“项目”旁的加号创建测试项目。
4. 在新项目首页确认记忆区域显示“文件”和编辑按钮。

全局个性化页面的用户档案和项目记忆也不是同一个数据源。修改前确认所处项目与作用域。

## 编辑与删除

1. 文件后端：点击记忆区域的编辑按钮，打开“编辑记忆”。
2. 切换到源码编辑 Markdown，保留短而明确的事实，点击“保存”。
3. 返回项目首页查看内容；刷新页面确认保存成功。删除某条笔记时编辑并移除对应内容，保存前检查其余内容未被误删。“重置”不是普通保存，请先备份。
4. 文件记忆按轮读取；已在执行的请求不会因编辑器保存而重新发送。下一轮再验证效果。向量后端使用条目管理方式，不能按单一 Markdown 文件理解。

避免把密钥、身份证件、完整私有资料或大段原始日志写入记忆。远程后端可能会将内容发送给相应服务，使用前检查配置。

## 选择后端

文件后端适合简单有界笔记；向量或外部后端有额外依赖、凭据和持久化要求。**WebUI 项目一旦启用记忆，便不能切换记忆后端。** 全局设置用于新项目，不提供现有数据自动迁移。需要另一后端时先备份，在新项目中配置并验证；不要直接移动运行中的数据库或复制被占用的锁文件。

```yaml
memory:
  unified_memory:
    storage:
      backend: file
```

这是核心配置片段，不是界面按钮的替代操作；具体存储和扩展接口见[记忆模块](../core/memory.md)。

## 向量记忆的模型配置

向量记忆使用两类模型，职责不同：

| 配置 | 作用 | 选择方式 |
| --- | --- | --- |
| 事实抽取模型 | 从对话提取值得长期保留的事实 | 跟随对话模型，或指定提供方和聊天模型 |
| 嵌入模型 | 将记忆编码为可检索的向量 | 固定提供方和嵌入模型，或本地离线嵌入 |

在 **设置 → 个性化 → 记忆设置** 配置新项目默认值，或在新建项目、编辑项目设置时配置该项目。候选列表可以辅助选择，也支持直接输入服务实际提供的模型 ID。建议在[模型设置](model-settings.md)标明“聊天 / 事实抽取”或“嵌入”用途；已标为嵌入的模型不能用于聊天，记忆配置检查也会拒绝把两种明确标记的用途混用。每轮召回条数默认是 10，可在界面设置为 1–50。

点击 **验证记忆配置** 检查凭据、端点和模型用途。配置有效时，验证会向所选远程嵌入服务发送小型探测请求来确认向量维度，可能产生少量调用费用。新建项目或保存改过的向量记忆模型配置时，表单也会先做验证，失败则不提交。本地嵌入检查可能读取本地模型信息，首次实际使用仍需下载模型。验证不创建记忆库，也不调用事实抽取模型，因此嵌入检查成功不等于整个记忆链路已验证。修改模型或提供方后需要重新验证。

本地模式需要在 `webui/backend/` 安装可选依赖：

```bash
uv sync --locked --extra local-embed
```

重启服务，等待首次模型下载完成后再使用。远程嵌入使用所选提供方已保存或环境变量中的凭据；显式选择不可用时会报告错误，不悄悄切换到另一服务。

嵌入模型在记忆库建立后固定，切换对话模型不会改变已有向量库的嵌入来源。若主动更换嵌入模型导致不匹配，可在项目记忆卡片点击 **重建**，用新模型重新编码现有条目；新库建成后才替换，旧库保留为备份。重建与切换后端不是同一操作。全局默认值只用于新项目，不自动修改现有记忆库。

## 没有记住或没有更新时

检查是否启用、作用域是否正确、后台写入是否完成、是否超出容量、当前后端是否执行自动提取。向量记忆状态会显示缺失凭据、嵌入验证失败或模型不匹配等配置问题；修复配置后再验证并尝试下一轮。记忆初始化失败时，该会话可继续聊天，但不会静默改用文件记忆。一次模型回答没提到某条事实，不足以证明存储失败；应检查内容或后端状态。停止任务或关闭服务前等待必要写入，避免将未完成的后台工作当作已保存。
