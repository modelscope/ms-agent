# 子智能体

子智能体让主Agent把专项工作交给独立执行上下文，再汇总结果。它不同于[工作流](workflows.md)的固定依赖图，也不同于通过ACP/A2A调用远端服务。

## 什么时候委派

适合边界清楚、能返回独立结果的任务，例如分别检查两份资料或独立分析模块。不要把互相依赖、持续争用同一文件的操作盲目并行化。

```{mermaid}
flowchart TD
 A[主智能体定义任务] --> B[子任务一 · 独立上下文]
 A --> C[子任务二 · 独立上下文]
 B --> D[结果与产物]
 C --> D
 D --> E[主智能体检查并汇总]
```

## 配置与发现

`AgentTool`支持 `agent_tools` 和兼容的 `split_task` 配置形式，插件还可提供Agent定义。工具是否出现取决于有效配置和装配结果，先用当前入口的工具列表确认。

```yaml
tools:
  split_task:
    mcp: false
```

这是启用工具的最小片段，不是完整的子任务配置；模型、权限和执行策略仍来自Agent/工具配置。具体参数应以运行时暴露的工具schema为准，避免在提示词中编造不存在的选项。

## 给子任务足够但有限的上下文

明确目标、输入文件、输出位置、完成条件和禁止范围。独立上下文不会自动继承主会话的全部细节；共享工作目录也不意味着并发写入安全。

主Agent应检查返回证据和产物，而不只接受“完成”一句话。失败、取消、超时和部分输出要分别处理；控制入口由[调度](scheduling.md)及任务控制工具等机制提供，不承诺任意后台任务跨进程恢复。

## 本地委派与协议集成

- 本地子智能体：使用SDK内部AgentTool和任务状态。
- [ACP](acp.md)/[A2A](a2a.md)：跨协议调用外部Agent，由对方服务管理执行。
- [Capability Gateway](capability-gateway.md)：把MS-Agent能力作为MCP工具暴露给宿主。

实现：`tools/agent_tool.py`、`tools/task_control_tool.py`、`plugins/agents.py`。
