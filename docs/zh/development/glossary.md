# 术语表

| 术语 | 本文档中的含义 | 不等同于 |
| --- | --- | --- |
| Agent / 智能体 | 组织模型、工具及执行状态的运行实体 | 单次LLM请求 |
| Harness | 围绕模型的执行、上下文、权限与反馈机制 | 一个固定UI或操作系统 |
| Provider / 提供方 | 模型服务注册和连接能力 | 模型ID或API协议 |
| Tool / 工具 | 有明确输入和结果的可调用操作 | 描述操作的提示词 |
| Skill / 技能 | 任务说明和按需参考/脚本资源 | 必然已经安装的工具 |
| Callback | 进程内Python生命周期扩展 | 外部脚本Hook |
| Hook | 事件上的脚本/决策扩展 | 所有插件能力 |
| Plugin / 插件 | 多类扩展资源的安装与装配单元 | 任意宿主代码均兼容 |
| Session / 会话 | 持续任务的消息记录与恢复状态 | 全局记忆 |
| Context / 上下文 | 当前模型可见消息与资料 | 完整历史日志 |
| Compaction / 压缩 | 在预算内重组/摘要模型输入 | 删除全部原始记录 |
| Memory / 记忆 | 跨任务复用知识及其后端 | 把所有聊天复制到文件 |
| Workspace / 工作目录 | 工具操作与产物的项目范围 | WebUI依赖目录 |
| Workflow / 工作流 | 显式阶段和依赖编排 | 模型任意自主委派 |
| MCP client / server | 消费工具 / 提供工具的两个方向 | ACP或A2A的别名 |
| RFC | 带状态的设计提案 | 已经发布的功能保证 |

首次出现概念时优先解释作用；细节见[核心模块](../core/configuration.md)和[架构](architecture.md)。历史项目可能保留旧命名，阅读时结合版本与当前实现。
