# 技能与 MCP

技能提供任务知识，MCP提供外部工具连接。把技能导入列表不等于已连接其要求的服务；连接成功也不意味着所有技能已启用。

## 使用一个技能

1. 在侧栏“Skill管理”或 **设置 → MCP与Skills** 打开技能列表。
2. 点击“添加 skill”，选择“上传文件夹”或“填写目录路径”。前者上传浏览器所在机器的目录；后者读取后端机器的绝对路径。文件夹需要包含 `SKILL.md` 和用到的参考/脚本；导入会复制整个目录，不是持续同步原目录。
3. 在项目或对话中的Skills选择器检查启用项及数量。
4. 请求一个与技能描述相符的小任务，检查是否实际加载说明和调用必要工具。

导入后列表出现技能卡片，可用开关启停，“更多”菜单提供该资源的管理操作。原目录后来变化时，应重新检查导入内容，不假设它已同步。托管模式可能隐藏填写本地路径的入口。

使用前审查脚本、依赖和访问范围。技能ID可能取目录名，frontmatter显示名称不能代替运行时ID。批量导入后先检查同名冲突和项目/全局作用域。

## 连接MCP

1. 打开“MCP管理”，点击“添加 MCP”填写单个服务，或用“通过 JSON 配置”编辑当前作用域的 `mcpServers` 对象。
2. stdio服务填写已安装命令、参数及必要环境变量；远程服务填写协议支持的URL/headers。JSON 编辑器保存的是整个作用域配置，修改前保留其他服务条目。
3. 保存后点击卡片上的“测试连接”按钮。成功提示为“服务名: 已连接”；失败时检查提示及日志。该探测不等于已执行工具。
4. 用卡片开关启用服务，再回到项目或对话输入框下的MCP选择器确认选择，请求一次范围明确的小调用。

配置中的路径属于运行后端的机器。若MCP进程找不到Python/Node，使用绝对可执行路径；不要把本机终端的PATH假设为远程服务PATH。

## 分清三种状态

| 状态 | 含义 |
| --- | --- |
| 已配置/导入 | 资源记录存在 |
| 已启用/选中 | 当前作用域选择了该资源 |
| 可调用 | 当前连接、依赖、凭据及权限满足条件 |

stdio 的初步检查只确认命令存在，显示“连接尚未验证”；“测试连接”会独立连接、初始化并读取工具列表。探测成功只针对这次连接，不会修复已打开会话，也不保证业务调用成功。

## 启动失败与重连

MCP 是可选能力，部分或全部服务启动失败时，普通聊天和内置工具仍可使用，界面提示缺失能力。卡片菜单的 **下轮重连相关会话** 会安排受影响会话在下一轮空闲时重建连接，当前回复继续，会话 ID 和历史保留。已禁用服务不会被重新启用，业务工具调用不自动重放。

远程自动检测最多等待 6 秒，手动测试最多 45 秒，服务自身更短的启动预算仍生效。若 MCP 命令临时下载依赖，先确认实际包下载可用，再测试完整初始化；仅有命令或软件源可达不足以证明服务可用。

## 失败时

技能不见了，先查目录结构和disabled/whitelist；MCP连不上，先查命令、参数、网络和认证。检查日志时移除Key、认证头和私人路径。外部服务返回文本不是无条件可信的系统指令。
