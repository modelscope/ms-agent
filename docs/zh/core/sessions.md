# 会话

会话把一段任务的输入、回复、工具结果和恢复状态联系起来。它解决“发生过什么、从哪里继续”，[上下文](context.md)解决“下一次给模型哪些内容”，[记忆](memory.md)则保存跨任务知识。

## 日志与可见窗口

`SessionLog` 使用追加记录保存消息和压缩事件。压缩后的视图也是新记录，不覆盖原消息。恢复时读取有效边界，避免把已压缩历史再次全部发送给模型。

```yaml
session_log:
  enabled: true
  context_limit: 128000
  reserved_buffer: 20000
compaction:
  enabled: true
```

`session_log.dir` 可显式指定目录。未设置时，SDK按工作目录将日志归入 `$MS_AGENT_HOME/projects/<key>/`；WebUI可以使用其管理的项目/会话目录。不要把日志位置固定写成 `output/sessions`。

## 会话由谁持有

| 场景 | 所有者与职责 |
| --- | --- |
| SDK直接运行 | Agent初始化日志、构造上下文并记录产出 |
| WebUI | 界面适配层管理会话选择和运行时，复用SDK存储与执行 |
| TUI | 根据工作目录选择/恢复会话，并把事件呈现到终端 |
| ACP/A2A | 协议适配器将外部会话或任务映射到内部运行 |

同一份工作目录不等于所有界面自动选择同一个会话。恢复应使用入口提供的会话选择，而不是复制一份日志并改ID。

## 会话分支

`manager.fork(session_id, after_seq=..., name=..., request_id=...)` 从已完成回复创建独立会话。`after_seq` 是日志中的完成位置，需通过回放验证工具调用与结果已配对，不是页面气泡序号。`request_id` 可为重复提交去重；同一 ID 不能用于不同分支点。

分支复制截至该回复的真实历史及有效压缩窗口，记录 `forked_from` 来源信息。计划仅从分支点前已保存的任务列表结果重建，没有相应快照时不继承源会话当前计划。后续聊天记录独立，项目文件、配置和记忆仍共享当前状态，分支不会回滚文件系统。

## 中断与持久化

正常回复会在等待下一次输入之前保存；中断轮保留实际发生的消息。WebUI 的待处理输入通过同一日志的 `input_event` 追加记录，服务重启后恢复为暂停，不自动重跑已投递消息。取消工具执行后应检查文件或外部操作的实际结果：保存日志不是回滚机制。

不要在服务运行时直接编辑JSONL或移动正在使用的存储。备份时同时保留应用元数据、会话记录和项目文件；换工作目录会影响默认项目键。

## 使用与排障

- WebUI从项目历史打开会话，TUI使用 `/sessions` 查看可用记录。
- 找不到历史时先检查工作目录、`MS_AGENT_HOME`及是否使用同一入口存储。
- 模型上下文过长时检查预算与压缩配置，不要删除原日志来“修复”窗口。

操作见[项目与会话](../user-guide/projects-sessions.md)，目录见[存储布局](../development/storage.md)。实现：`session/session_log.py`、`project/session.py`、`project/fork.py`、各入口运行时。
