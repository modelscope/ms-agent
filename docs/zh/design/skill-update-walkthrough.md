# Skill 管理：人工走查清单

先启动本分支的 WebUI，并创建独立测试项目；不要覆盖日常使用的 Skill。构建启动方式见 [WebUI 指南](../../../webui/README_ZH.md)。设计和代码说明见[开发概要](skill-update-implementation.md)。

## 安装与来源

| 完成 | 操作 | 应看到的结果 |
| --- | --- | --- |
| ☐ | 添加 Skill → 从链接安装，输入公共 GitHub 仓库 / 子目录 | 发现真实候选，来源和安装位置可确认；多候选可多选 |
| ☐ | 输入 ModelScope Skill 页面链接 | 安装记录保存条目的精确 ID 和提交，来源详情可查看 |
| ☐ | 输入 `https://modelscope.cn/collections/Gaodekaifangpingtai/gaodekaifangpingtai-skill` | 展示当前合集的候选及每个仓库来源；无法读取项单独标记 |
| ☐ | 在有同名候选的合集中全选，再手动择一 | 无歧义项可批量选中，同名项不会互相覆盖 |
| ☐ | 安装多个候选，需要时查看并确认静态检查 | 显示逐项进度；成功项出现于目标作用域，安装不执行包内脚本 |
| ☐ | 再次解析同一来源 | 已安装项不可重复勾选，其他同名来源显示冲突 |
| ☐ | 从本地导入，再在详情中关联来源 | 内容一致只补记录；不一致先明确确认备份替换 |

## 更新、恢复与执行边界

准备一个自己控制的测试仓库：先发布并安装 V1，再提交 V2。测试内容可只包含 `SKILL.md` 和一个带版本标记的普通文件，无需增加长期维护的示例项目。不要修改第三方仓库。

| 完成 | 操作 | 应看到的结果 |
| --- | --- | --- |
| ☐ | 点击检查更新 | 内容变化显示“待更新”，同仓库其他 Skill 的变化不误报 |
| ☐ | 打开更新，查看文件差异并确认 | 文本 diff 正确；二进制和权限变化可辨认；成功提示“已更新” |
| ☐ | 在同一会话的下一回合要求实际读取该 Skill 的版本标记 | 工具读取新版内容，能在调用记录中核对 |
| ☐ | 恢复旧版，再检查更新 | 恢复 V1，重新出现待更新 |
| ☐ | 本地新增自定义文件后更新 | 显示“本地有修改”，默认不覆盖；确认覆盖后可恢复自定义文件 |
| ☐ | 预览后再修改本地文件，随后确认 | 旧计划失效，要求重新预览 |
| ☐ | 运行同作用域模型任务时更新 / 删除 | 提示任务运行中；任务结束或停止后可重试 |
| ☐ | 对合集中的单个安装重复上述操作 | 更新和恢复只影响该成员；合集成员变更不自动增删本地内容 |

## 取消、失败与界面

| 完成 | 操作 | 应看到的结果 |
| --- | --- | --- |
| ☐ | 下载中取消并重新打开弹窗 | 不留下半安装目录或迟到进度 |
| ☐ | 批次部分失败后重试 | 保留成功项，只重新处理失败项 |
| ☐ | 模拟列表请求失败后重试 | 已有卡片保留；首次失败不冒充空列表 |
| ☐ | 加载期间切换全局 / 项目 | 旧响应不覆盖新作用域 |
| ☐ | 关闭自动检查，再手动检查 | 自动检查停用，手动检查仍可用 |
| ☐ | 切换中文 / 英文、明暗主题，缩窄窗口 | 长来源可辨认，无横向溢出，滚动和底部操作可用 |

事务中断、恶意归档、凭据重定向和并发竞争使用自动化测试验证；不要在日常工作空间故意制造这些故障。公开来源会变化，验收应核对实际成员和提交，不能依赖固定候选数量。
